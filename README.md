# Царские конюшни — сайт с Pages CMS

Простой сайт конного клуба (HTML/CSS/JS) и **Pages CMS**, без платного бэкенда.

## Тестируем локально

1. Распакуйте архив.
2. Установите Python (если его нет) и откройте терминал в папке с `index.html`.
3. Запустите `python -m http.server 8000` (на Windows может потребоваться `py -m http.server 8000`).
4. Откройте `http://localhost:8000/`.

Не открывайте `index.html` двойным щелчком: браузер блокирует загрузку JSON через `file://`.

## Что редактирует владелец клуба в Pages CMS

| Раздел CMS | Файл | Что можно менять |
|---|---|---|
| Главная страница | `data/site.json` | Название, логотип, девиз, подписи и текст приглашения |
| Услуги клуба | `data/services.json` | Добавление, скрытие, порядок услуг, описания и пункты |
| Прайс | `data/prices.json` | Названия услуг, цены и дополнительные условия |
| Контакты и адрес | `data/contacts.json` | Telegram, WhatsApp, телефон, Instagram, Яндекс Карты, адрес |
| Фотогалерея | `data/gallery.json` | Загрузка/удаление фото и подписи |

Файл `.pages.yml` содержит готовую схему редактора. Изображения хранятся в `assets/uploads/`.
Контакты не придуманы: они пустые. Пока сайт в режиме демо, их отсутствие обозначено в интерфейсе.
**При запуске клуба** заполните контакты/прайс и отключите «Показывать отметку о демо-версии».

## Разместить проект и подключить CMS

1. Создайте репозиторий на GitHub. Выложите **содержимое папки**, в том числе скрытый файл `.pages.yml` (нельзя терять точку в начале).
2. Настройте Pages: `Settings → Pages → Deploy from a branch → main / (root)`.
3. Откройте [app.pagescms.org](https://app.pagescms.org/) под владельцем GitHub-репозитория.
4. Установите GitHub App Pages CMS с доступом **только к этому репозиторию** и откройте его в CMS.
5. Проверьте разделы «Главная страница», «Услуги клуба», «Прайс», «Контакты и адрес», «Фотогалерея».
6. Если редактировать будет человек без GitHub, пригласите его как collaborator по email из интерфейса Pages CMS.
7. Для проверки измените девиз и сохраните. После коммита и публикации GitHub Pages обновите сайт. Восстановите прежнее значение.

**Это не локальная админка с паролем**: внешний Pages CMS выполняет вход и запись в GitHub. Логины/пароли нельзя добавлять в HTML или JSON.

## Что проверено

Структура JSON и `.pages.yml`, функциональность отрисовки, модальных карточек, меню, чтение изменённых JSON и режим пустых контактов проверяются локально. Настоящая запись из Pages CMS в GitHub и вход реального редактора требуют подключённого репозитория и авторизации; локальное тестирование их не заменяет.

## Ограничение GitHub Pages

GitHub Pages не предназначен для бесплатного хостинга сайтов, основной целью которых является ведение онлайн-бизнеса или коммерческие транзакции: https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits . Для пробной страницы это удобная платформа, но для рабочего коммерческого сайта нужно учитывать условия сервиса. При переезде на другой статический хостинг сайт и JSON сохранят работоспособность (а Pages CMS может продолжить редактировать GitHub-репозиторий).

## Адреса изображений

Pages CMS сохраняет изображения как `/assets/uploads/...`, а сайт переводит их в относительные URL, поэтому они открываются в GitHub Pages даже если адрес содержит `/имя-репозитория/`.
